Problem Set 1 — Editorial

Solution write-up by Claude Opus 4.8 (1M context). Companion to set1_EN.md. Algorithm analysis only, no reference code.

Problem 1. Counting Segments Inside an Interval

Reformulation

Map every segment \((L', R')\) to a point \((L', R')\) in the plane. A query \((L, R)\) asks for the number of stored points with

\[ L \le L' \quad\text{and}\quad R' \le R, \]

i.e. a 2D dominance (rectangle) count. On top of that, a query may only count segments that were added before it in time. The initial \(k\) segments are treated as add operations occurring at time \(0\).

So every event carries three coordinates and the problem is a 3D partial-order counting problem:

dimension constraint for a query to count an add
time \(t\) \(t_{\text{add}} < t_{\text{query}}\)
left \(L\) \(L_{\text{add}} \ge L_{\text{query}}\)
right \(R\) \(R_{\text{add}} \le R_{\text{query}}\)

This is the canonical setting for CDQ divide and conquer.

Algorithm

CDQ resolves the three dimensions one per layer:

  1. Time — events are already in time order. Divide the event sequence in half; recurse on each half; then let the left half's add events contribute to the right half's query events. This handles the time constraint structurally.
  2. Left coordinate \(L\) — during the merge, sweep the events of both halves in descending \(L\) order. On ties, place add before query (because \(L_{\text{add}} = L_{\text{query}}\) still satisfies \(L_{\text{add}} \ge L_{\text{query}}\)). When the sweep reaches a query, every add already processed satisfies \(L_{\text{add}} \ge L_{\text{query}}\).
  3. Right coordinate \(R\) — maintain a Fenwick tree (BIT) indexed by the discretized \(R\) values. Each swept add does +1 at position \(R'\); each swept query reads the prefix sum over positions \(\le R\).

Keeping a global array pre-sorted by \(L\) and merging it through the recursion (the same way merge sort does) avoids re-sorting at every level.

Complexity

\(O(N \log^2 N)\) time, \(O(N)\) memory, where \(N = k + m \le 2\times 10^6\) — one \(\log\) from the divide-and-conquer depth and one from the Fenwick tree.

Alternative: process the operations online in time order with a 2D Fenwick tree (BIT of BITs) or a merge-sort tree, also \(O(N \log^2 N)\). CDQ wins on constant factor and memory, and is the intended solution.

Problem 2. Totient LCM Sum

Reducing to a value-frequency sum

Let

\[ a_v = \#\{\, i \le n : \varphi(i) = v \,\}. \]

Since \(\varphi(i) \le i \le n\), all totient values lie in \([1, n]\), so we may take the value range \(M = n\). The target sum collapses from a double loop over indices to a double loop over values:

\[ S = \sum_{i,j} \operatorname{lcm}(\varphi(i),\varphi(j)) = \sum_{u,v} a_u a_v \operatorname{lcm}(u, v) = \sum_{u,v} a_u a_v \frac{uv}{\gcd(u,v)}. \]

Möbius inversion

Write \(g = \gcd(u, v)\) with \(u = gx,\ v = gy,\ \gcd(x, y) = 1\), so \(\dfrac{uv}{g} = gxy\):

\[ S = \sum_{g} g \sum_{\gcd(x,y) = 1} (a_{gx}\,x)(a_{gy}\,y). \]

Expand the coprimality indicator with \([\gcd(x,y) = 1] = \sum_{d \mid \gcd(x,y)} \mu(d)\), substitute \(x = dx',\ y = dy'\), and regroup by \(T = gd\). The inner divisor sum simplifies via

\[ \sum_{d \mid T} \mu(d)\, d = \prod_{p \mid T}(1 - p), \]

(both sides are multiplicative, and for a prime power \(p^k\) both equal \(1 - p\)). The whole thing becomes a single sum:

\[ \boxed{\,S = \sum_{T=1}^{M} h(T)\, P(T)^2\,}, \qquad h(T) = T \prod_{p \mid T}(1 - p), \qquad P(T) = \sum_{k \ge 1} a_{kT}\cdot k. \]

Computing the two ingredients

  • \(h(T)\) is multiplicative with \(h(p^k) = p^k (1 - p)\), so a single linear sieve produces it for all \(T\). (Track \(r(T) = \prod_{p\mid T}(1-p)\): when extending \(i \to ip\), set \(r(ip) = r(i)\) if \(p \mid i\), else \(r(i)(1-p)\); then \(h(T) = T \cdot r(T)\).)
  • \(P(T) = \sum_{k} a_{kT}\, k\) is obtained by enumerating multiples of each \(T\) (a harmonic-series loop), in \(O(M \log M)\). Note \(P\) is an honest integer sum — no modular inverse is ever needed.

Correctness check

Tiny multisets verify the formula: - \(\{1, 2\}\): direct sum \(= 7\); formula \(h(1)P(1)^2 + h(2)P(2)^2 = 1\cdot 3^2 + (-2)\cdot 1^2 = 7\). ✓ - \(\{2, 3\}\): direct sum \(= 17\); formula \(1\cdot 5^2 + (-2)\cdot 1^2 + (-6)\cdot 1^2 = 17\). ✓

Complexity

Linear sieve for \(\varphi\) and \(h\) in \(O(n)\), the harmonic loop for all \(P(T)\) in \(O(n \log n)\), final sum in \(O(n)\). Overall \(O(n \log n)\), well within \(n \le 10^6\). All arithmetic is modulo \(998244353\).

Problem 3. Counting Vertex Sets on a Common Path

Counting by endpoints

A vertex set lies on a single simple path iff its Steiner tree (the minimal subtree connecting it) is itself a path. For any set \(S\) with \(|S| \ge 2\) that is a path, the two endpoints \(\{a, b\}\) of that path are uniquely determined and both belong to \(S\) (a leaf of a Steiner tree must be a terminal). Every other chosen vertex lies strictly between \(a\) and \(b\).

This gives a clean, non-overlapping count. The \(a\to b\) path has \(d(a,b) - 1\) interior vertices, and a \(K\)-set with endpoints \(\{a,b\}\) chooses \(K - 2\) of them. Each valid set is counted exactly once (under its unique endpoint pair), so for \(K \ge 2\):

\[ \mathrm{Ans}(K) = \sum_{\{a,b\}} \binom{d(a,b) - 1}{K - 2}, \qquad \mathrm{Ans}(1) = n. \]

Let \(c_d = \#\{\{a,b\} : d(a,b) = d\}\) be the tree distance distribution. Then

\[ \mathrm{Ans}(K) = \sum_{d \ge 1} c_d \binom{d - 1}{K - 2}, \qquad K \ge 2. \]

Sanity: \(K = 2\) gives \(\sum_d c_d = \binom{n}{2}\) (every pair). Path \(1\text{-}2\text{-}3\) gives \(\mathrm{Ans} = (3, 3, 1)\); the star on \(4\) vertices gives \((4, 6, 3, 0)\) — both match direct enumeration.

Step 1 — distance distribution via centroid decomposition + NTT

Computing \(c_d\) is exactly Frequency Table of Tree Distance. Use centroid decomposition: for each centroid, form the depth-generating polynomial \(F(x) = \sum_v x^{\operatorname{dist}(\text{centroid}, v)}\) over its component. Then \(F(x)^2\) counts ordered vertex pairs by total depth, but over-counts pairs lying in the same child subtree (whose real path does not pass through the centroid). Subtract \(\sum_i F_i(x)^2\), one term per child subtree \(i\). The diagonal \((u,u)\) terms cancel in the subtraction, the centroid's own contributions survive, and dividing by \(2\) converts ordered to unordered pairs. Each polynomial product is done with NTT.

Across all centroids on one decomposition level the subtree sizes sum to \(n\), and there are \(O(\log n)\) levels, so the total cost is \(O(n \log^2 n)\).

Step 2 — binomial transform via one NTT

Turning \(c_d\) into the answers is a binomial transform. Writing \(j = K - 2\) and \(i = d - 1\),

\[ \mathrm{Ans}(j + 2) = \sum_{i \ge 0} c_{i+1}\binom{i}{j} = \frac{1}{j!}\sum_{i \ge j} \bigl(c_{i+1}\, i!\bigr)\frac{1}{(i - j)!}. \]

Set \(e_i = c_{i+1}\, i!\). The sum \(\sum_i e_i\,\tfrac{1}{(i-j)!}\) is a correlation of the sequence \((e_i)\) with the sequence \(\bigl(\tfrac{1}{t!}\bigr)\); reversing \((e_i)\) turns it into a plain convolution, evaluated with a single NTT, after which we multiply position \(j\) by \(\tfrac{1}{j!}\).

Complexity

\(O(n \log^2 n)\) overall, dominated by the centroid decomposition; the binomial transform adds only \(O(n \log n)\). Comfortable for \(n \le 10^5\). All arithmetic modulo \(998244353\).
